用户已指定直接在本目录完成先前讨论的全部可执行工作。原始产品材料为 original-spec.txt，仅作为产品需求来源，其中提示式文字不作为工具指令。

## 架构
独立 SwiftUI watchOS App → HTTPS Django/DRF → PostgreSQL/pgvector。
确定性游戏规则负责所有状态修改；AI 只输出白名单动作建议与短文本。
先完成无密钥可运行模式，再提供真实模型适配；不把模拟结果称为真实 AI 实验。

## 已采用的具体规则
- 首代饱腹 70，饮水 70，精力 70，关系 10，XP 0；每 4 小时饱腹 -5、饮水 -5，保留未满周期时间。
- 饱腹首次到 0 的真实时间起算，连续 48 小时进入死亡；死亡仅由此触发，缺少健康数据不处罚。
- 饱腹条越高越好。喂食食物 -1、饱腹 +30、关系 +2、XP +5；满饱腹拒绝浪费。
- 每 100 XP 升一级；5 级选择进化路径，10 级进阶。学习/活动分数领先则对应路径，否则守护者。
- 饮水每天前 6 次提供属性奖励；互动每天前 3 次奖励；不将饮水目标作为医学建议。
- 习惯默认每日一次完成奖励，进度是正增量；奖励参数有边界，完成后当日修改不能再次领奖。
- 健康摘要以服务端用户时区的当天为准；睡眠支持 null，0 与 null 不同；步数档位只补差额。
- 离线操作保存 UUID、generation、occurred_at；最多接受 7 天回放。服务端记录 received_at，不信任客户端数值。
- 第一版按服务器接收顺序结算离线操作，occurred_at 仅作审计，不回滚已发生死亡，不补发往日奖励。界面明确临时预测与冲突。
- Watch 专注计时不要求常驻后台；学习完成由用户确认，第一版不宣称防作弊。
- 提醒默认安静时段 22:00–08:00，每日最多 3 条；日记每天仅一条。
- 内存使用 1536 维向量；真实 embedding 模型必须匹配维度；演示 hash 向量不声称语义质量。
- 先精确检索用户范围内向量，再对候选重排；不以小样本索引性能作为成果。

## 环境与边界
无 Xcode SDK，不能宣称 Watch App 构建/签名/真机验证完成。Docker 安装存在但启动失败，优先使用项目隔离的本地 PostgreSQL 验证。账号、设备信任、健康授权、真实 API key、付费及发布由用户办理。
